# PRD: بازطراحی فضای کاربری حساب، خرید مستقیم و تالار اعلام بار

## Summary

فضای کاربری فعلی نام‌های نزدیک به هم دارد و کاربر به‌راحتی «سفارشات»، «خریدهای مستقیم»، «سبد خرید» و «پرداخت‌ها» را با هم قاطی می‌کند. این تغییر، حساب کاربری را از ظاهر سایت عمومی جدا می‌کند و آن را به یک پنل کاری شبیه داشبورد ادمین تبدیل می‌کند.

## Problem

- مسیر `/orders` برای تالار اعلام بار کاربران است، اما با عنوان سفارشات نمایش داده می‌شود.
- مسیر `/account/purchases` مربوط به خرید مستقیم از کاوه متال است، اما در کنار سفارشات و سبد خرید ابهام ایجاد می‌کند.
- صفحات حساب کاربری داخل هدر و فوتر سایت عمومی قرار دارند و حس پنل عملیاتی ندارند.
- داشبورد کاربر از نظر اولویت کاری، پرداخت‌های معوق، سبد خرید و آخرین خریدها را به اندازه کافی واضح جدا نمی‌کند.

## Goals

- جدا کردن زبان UI:
  - «تالار اعلام بار» برای درخواست‌های خرید/فروش کاربران سایت.
  - «خرید مستقیم از کاوه متال» برای سفارش‌هایی که از محصولات خود سایت ثبت شده‌اند.
  - «سبد خرید مستقیم» برای جمع‌کردن کالا قبل از تسویه.
  - «تسویه‌ها» برای پرداخت‌های در انتظار، مهلت‌ها و سوابق پرداخت.
- حذف هدر و فوتر سایت عمومی از فضای حساب کاربری و ساختن یک workspace تمام‌صفحه.
- نزدیک کردن shell حساب کاربری به ادمین داشبورد: sidebar ثابت، topbar، کارت‌های آماری، actionهای روشن.
- حفظ مسیرهای API و routeهای موجود تا لینک‌ها نشکنند.

## Non-Goals

- تغییر مدل دیتابیس یا API فروش مستقیم در این مرحله انجام نمی‌شود.
- مسیر `/orders` از نظر دامنه کاری بازنویسی نمی‌شود؛ فقط نام‌گذاری و لینک‌دهی آن شفاف‌تر می‌شود.
- اتصال درگاه پرداخت یا پیامک واقعی در این تغییر انجام نمی‌شود.

## User Experience

### Navigation Labels

- `/account/dashboard`: «پیشخوان خرید مستقیم»
- `/cart`: «سبد خرید مستقیم»
- `/account/purchases`: «خریدهای من از کاوه»
- `/account/payments`: «تسویه‌ها و پرداخت‌ها»
- `/orders`: «تالار اعلام بار»
- `/account`: «پروفایل»
- `/account/kyc`: «احراز هویت»
- `/account/seller`: «پنل فروشنده»

### Dashboard Layout

- Sidebar سمت راست با زمینه تیره مشابه ادمین.
- Topbar ثابت با نام کاربر، جستجوی سریع ظاهری، لینک بازگشت به قیمت‌ها و اعلان ساده.
- Mobile navigation به صورت chipهای افقی.
- محتوای داشبورد شامل:
  - کارت وضعیت سبد خرید.
  - کارت خریدهای مستقیم.
  - کارت تسویه‌های در انتظار.
  - کارت مهلت گذشته.
  - بخش «اقدام بعدی» برای واضح‌ترین کار فوری.
  - بخش «آخرین خریدهای مستقیم».
  - بخش توضیحی کوتاه برای تفاوت خرید مستقیم و تالار اعلام بار.

## Acceptance Criteria

- کاربر در حساب کاربری هدر و فوتر سایت عمومی را نبیند.
- کاربر در منو گزینه‌ای با عنوان مبهم «سفارشات» برای تالار اعلام بار نبیند.
- داشبورد کاربر با sidebar/topbar شبیه ادمین داشبورد نمایش داده شود.
- سبد خرید و خرید مستقیم به صورت واضح جدا از تالار اعلام بار نام‌گذاری شوند.
- build و lint فرانت بدون error پاس شوند.

## Implementation Notes

- `AppShell` باید برای `/account`, `/cart`, `/checkout` و `/orders` هدر/فوتر عمومی را حذف کند.
- `app/account/layout.js` باید shell عملیاتی جدید را مالک شود.
- `app/components/Sidebar.js` یا حذف می‌شود یا دیگر در layout حساب استفاده نمی‌شود.
- صفحات حساب لازم نیست route عوض کنند؛ فقط نام‌گذاری و UI آنها اصلاح می‌شود.
