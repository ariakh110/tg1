# PRD: اصلاح وزن تقریبی ورق، داشبورد کاربر و نوتیفیکیشن‌ها

## Summary

این سند سه اصلاح مرتبط با تجربه خرید مستقیم کاوه متال را تعریف می‌کند:

1. محاسبه وزن تقریبی ورق باید با فرمول بازار انجام شود.
2. UI اضافی بالای داشبورد کاربر حذف شود تا صفحه خلوت‌تر و حرفه‌ای‌تر شود.
3. زنگوله نوتیفیکیشن در داشبورد کاربر باید به داده واقعی وصل شود و فقط عدد تزئینی نباشد.

## Problems

### 1. وزن تقریبی ورق

در خرید با واحد «تعداد ورق»، وزن تقریبی باید از ابعاد و تعداد محاسبه شود. فرمول مورد انتظار:

```text
وزن تقریبی کیلوگرم =
ضخامت ورق به میلی‌متر × عرض ورق به متر × طول ورق به متر × 8 × تعداد ورق
```

تعداد ورق باید حداقل ۱ باشد.

نمونه:

```text
ورق ۲ میل، عرض ۱.۵ متر، طول ۶ متر، تعداد ۱۰
۲ × ۱.۵ × ۶ × ۸ × ۱۰ = ۱۴۴۰ کیلوگرم
```

### 2. UI داشبورد کاربر

بخش بالایی داشبورد کاربر که دوباره عنوان و دکمه‌های «لیست قیمت‌ها» و «تالار اعلام بار» را نشان می‌دهد، صفحه را شلوغ کرده و با سایدبار تکراری است. این بخش باید حذف یا به یک هدر بسیار ساده تبدیل شود.

### 3. زنگوله نوتیفیکیشن

زنگوله بالای داشبورد کاربر فعلاً فقط عدد ثابت نشان می‌دهد و با وضعیت واقعی کاربر هماهنگ نیست. باید از API نوتیفیکیشن/هشدارهای سفارش خوانده شود.

## Goals

- محاسبه وزن ورق با فرمول قابل فهم بازار انجام شود.
- کاربر بتواند تعداد ورق را آزاد وارد کند، ولی کمتر از ۱ مجاز نباشد.
- اگر طول ورق مشخص نیست، واحد «تعداد ورق» برای آن محصول فعال نشود مگر ادمین برای tier طول قیمت‌گذاری تعریف کرده باشد.
- داشبورد کاربر ساده‌تر شود و اطلاعات تکراری بالای صفحه حذف شود.
- زنگوله نوتیفیکیشن تعداد هشدارهای واقعی کاربر را نشان دهد.

## Non-Goals

- اتصال به سرویس push notification مرورگر در این مرحله لازم نیست.
- SMS notification در این PRD پیاده‌سازی نمی‌شود.
- تغییر کامل طراحی داشبورد ادمین در این سند نیست.

## Functional Requirements

### Requirement 1: محاسبه وزن تقریبی ورق

سیستم باید برای محصولاتی که با واحد `sheet` خرید می‌شوند، وزن تقریبی را با فرمول زیر محاسبه کند:

```text
thickness_mm × width_m × length_m × 8 × sheet_count
```

قوانین:

- `thickness_mm` از مشخصات محصول خوانده شود.
- `width_m` از عرض tier انتخاب‌شده یا مشخصات محصول خوانده شود و از میلی‌متر به متر تبدیل شود.
- `length_m` از طول tier انتخاب‌شده یا مشخصات محصول خوانده شود و از میلی‌متر به متر تبدیل شود.
- `sheet_count` باید عدد صحیح یا اعشاری معتبر نباشد؛ برای تعداد ورق فقط عدد صحیح ۱ یا بیشتر مجاز است.
- اگر ضخامت، عرض یا طول موجود نبود، سیستم وزن را «نامشخص» نشان دهد و اجازه ثبت سفارش با تعداد ورق را ندهد.
- برای رول یا کویل بدون طول مشخص، واحد تعداد ورق نباید نمایش داده شود.

### Requirement 2: انتخاب tier قیمت بر اساس مقدار

سیستم باید قبل از افزودن به سبد و قبل از ثبت سفارش، tier قیمت را بر اساس مقدار درخواستی انتخاب/اعتبارسنجی کند.

قوانین:

- اگر مبنای tier `kg` باشد، مقدار درخواستی به کیلوگرم تبدیل شود.
- اگر مبنای tier `ton` باشد، مقدار درخواستی به تن تبدیل شود.
- اگر مبنای tier `sheet` باشد، تعداد ورق با `minimum_quantity` و `maximum_quantity` مقایسه شود.
- اگر tier انتخاب‌شده با مقدار درخواستی سازگار نیست، سیستم باید بهترین tier سازگار را انتخاب کند یا پیام بدهد که قیمت برای این مقدار تعریف نشده است.

### Requirement 3: اصلاح نمایش و ورود مقدار خرید

ورودی مقدار خرید نباید dropdown باشد.

قوانین:

- برای `ton` و `kg` مقدار عددی آزاد قابل ورود باشد.
- برای `sheet` مقدار باید عدد صحیح ۱ یا بیشتر باشد.
- خطای مقدار نامعتبر باید فارسی و نزدیک همان input نشان داده شود.
- محاسبه قیمت و وزن باید همزمان با تغییر مقدار به‌روز شود.

### Requirement 4: حذف UI اضافه داشبورد کاربر

بخش بالایی تکراری داشبورد کاربر باید حذف شود.

قوانین:

- عنوان اصلی داشبورد فقط یک بار نمایش داده شود.
- دکمه‌های سریع «لیست قیمت‌ها» و «تالار اعلام بار» اگر لازم هستند داخل محتوای داشبورد بمانند، نه در هدر تکراری بالای صفحه.
- فضای بالای صفحه نباید یک band بزرگ خالی یا تکراری داشته باشد.

### Requirement 5: نوتیفیکیشن کاربر

زنگوله داشبورد باید داده واقعی داشته باشد.

منابع هشدار در فاز اول:

- سفارش مستقیم با مهلت پرداخت گذشته.
- سفارش مستقیم با مانده قابل پرداخت.
- سفارش مستقیم با اعتبار قیمت منقضی‌شده.
- پیام یا notification ثبت‌شده برای سفارش مستقیم.

قوانین:

- badge زنگوله باید تعداد هشدارهای خوانده‌نشده/فعال را نشان دهد.
- اگر هشدار وجود ندارد، badge نمایش داده نشود.
- کلیک روی زنگوله باید یک dropdown ساده با آخرین هشدارها باز کند.
- هر هشدار باید لینک مستقیم به صفحه مربوطه داشته باشد.

## API Requirements

### Backend

- در محاسبه وزن sheet از ضریب ۸ استفاده شود، نه ۷.۸۵.
- endpoint خلاصه داشبورد کاربر باید `notification_count` و `notifications` برگرداند یا endpoint مستقل برای notification ساخته شود.
- اگر سفارش با واحد sheet و بدون طول معتبر ارسال شود، API باید 400 بدهد.

### Frontend

- helper محاسبه وزن باید با بک‌اند هم‌فرمول باشد.
- زنگوله account layout باید از API داده بخواند.
- UI مقدار خرید باید input عددی باشد و برای sheet مقدار کمتر از ۱ را نپذیرد.

## Acceptance Criteria

### AC1: محاسبه وزن ورق

Given محصول ورق با ضخامت ۲ میلی‌متر، عرض ۱۵۰۰ میلی‌متر و طول ۶۰۰۰ میلی‌متر  
When کاربر تعداد ۱۰ ورق انتخاب کند  
Then وزن تقریبی باید ۱۴۴۰ کیلوگرم باشد.

### AC2: قیمت کیلویی

Given قیمت واحد ۱۴۰٬۰۰۰ تومان به ازای کیلوگرم  
When کاربر ۵۰ تن انتخاب کند  
Then مبلغ باید ۷٬۰۰۰٬۰۰۰٬۰۰۰ تومان باشد.

### AC3: مقدار ورق نامعتبر

Given واحد خرید `sheet` است  
When کاربر مقدار ۰ یا مقدار خالی وارد کند  
Then سیستم باید خطای فارسی بدهد و اجازه افزودن به سبد ندهد.

### AC4: رول بدون طول

Given محصول رول طول مشخص ندارد  
When کاربر وارد مرحله خرید شود  
Then گزینه `تعداد ورق` نمایش داده نشود.

### AC5: نوتیفیکیشن

Given کاربر یک سفارش با مهلت پرداخت گذشته دارد  
When داشبورد را باز می‌کند  
Then زنگوله badge واقعی نشان دهد و dropdown هشدار لینک همان سفارش را داشته باشد.

### AC6: حذف UI اضافه

Given کاربر وارد `/account/dashboard` می‌شود  
Then band بالایی تکراری با دکمه‌های انتخابی حذف شده باشد و عنوان داشبورد فقط یک‌بار دیده شود.
