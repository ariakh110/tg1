# PRD: کنترل زمان و توقف درخواست دستیار سئو

## مسئله

آدیت یک URL ممکن است شامل embedding، بازیابی دانش، واکشی صفحه و چند تماس با مدل باشد. timeout مشترک ۳۰ ثانیه‌ای برای AvalAI کافی نیست و کاربر پس از انتظار، خطای `read operation timed out` می‌گیرد. هم‌زمان رابط هیچ کنترل توقفی ندارد و پاسخ دیررس ممکن است پس از منصرف‌شدن کاربر در تاریخچه ثبت شود.

## هدف

- زمان پاسخ AvalAI برای دستیار سئو مستقل و قابل تنظیم باشد.
- مقدار پیش‌فرض ۹۰ ثانیه و بازه مجاز ۳۰ تا ۱۱۰ ثانیه باشد تا حاشیه‌ای پیش از timeout ۱۲۰ ثانیه‌ای Cloudflare باقی بماند.
- هنگام پردازش، کنترل واضح «توقف پردازش» در دسترس باشد.
- توقف رابط فوری باشد و backend نیز اجرای متناظر را لغوشده ثبت کند.
- اجرای لغوشده پاسخ، پیام ابزار یا مرحله بعدی در تاریخچه باقی نگذارد.
- ارسال تکراری یک شناسه تکمیل‌شده باعث هزینه دوباره مدل نشود.

## نیازمندی‌های عملکردی

1. هر ارسال گفتگو یک UUID مستقل داشته باشد.
2. backend وضعیت `running/completed/cancelled/failed`، مالک و زمان پایان را نگهداری کند.
3. endpoint لغو فقط برای ادمین احراز هویت‌شده و به‌صورت idempotent عمل کند.
4. لغوی که زودتر از درخواست اصلی می‌رسد مانع اجرای بعدی همان UUID شود.
5. رابط با `AbortController` انتظار fetch را فوراً قطع کند و سپس لغو backend را ارسال کند.
6. در زمان پردازش، دکمه ارسال با دکمه قرمز توقف و آیکن استاندارد جایگزین شود.
7. timeout از بخش تنظیمات دستیار سئو قابل ویرایش و در backend محدود شود.

## معیار پذیرش

- پاسخ ۳۱ تا ۹۰ ثانیه‌ای با تنظیم پیش‌فرض دیگر به timeout قبلی برخورد نکند.
- انتخاب توقف، وضعیت انتظار را فوراً ببندد و پیام «پردازش این درخواست متوقف شد» نشان دهد.
- پاسخ دیررس اجرای لغوشده در گفتگوی فعلی و گفتگوهای قبلی ظاهر نشود.
- لغو پیش از ایجاد run نیز provider را اجرا نکند.
- retry همان UUID تکمیل‌شده پاسخ ذخیره‌شده را برگرداند.
- timeout سایر سرویس‌ها تغییر نکند.

## محدودیت فنی

AvalAI/OpenAI-compatible API قرارداد عمومی برای لغو اجباری یک completion غیرstreaming ندارد. اگر لغو دقیقاً وسط read مسدودکننده رخ دهد، پردازش upstream ممکن است تا پاسخ یا timeout ادامه پیدا کند؛ برنامه نتیجه را دور می‌اندازد و ابزار/تماس بعدی را اجرا نمی‌کند.

## انتشار

1. migration اپ `seo_assistant` اجرا شود.
2. backend و frontend هم‌زمان منتشر شوند.
3. تنظیم «مهلت پاسخ سرویس» در پنل روی ۹۰ ثانیه بررسی شود.
4. یک درخواست آدیت واقعی ارسال و یک درخواست دیگر حین اجرا متوقف شود.
