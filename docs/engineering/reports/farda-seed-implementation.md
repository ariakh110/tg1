# تحویل seed نبشی و ناودانی — ۲۰۲۶/۱۱/۰۵

وضعیت: پیاده‌سازی محلی و آزمون‌ها انجام شده؛ بازبینی مستقل نهایی در ادامه ثبت
می‌شود. هیچ واردسازی روی دیتابیس توسعه/سرور یا انتشار انجام نشده است.

## دامنه و داده

تأیید مالک «بله» برای طرح ارائه‌شده و «هر طور صلاح میدونی عمل کن» برای انتخاب
پوشه/شاخه ثبت شد. کار روی `dev-ariakhayer` باقی ماند؛ merge یا push نشده است.
مرجع: `openspec/changes/add-angle-channel-catalog-seed/` و طرح اجرایی
`docs/superpowers/plans/2026-11-05-farda-sections-seed.md`.

از snapshot بررسی‌شدهٔ فردا فولاد، ۱۴۹ کالای مستقل آماده است: ۸۴ نبشی و ۶۵ ناودانی؛
۸ دسته، ۱۶ گزینهٔ کارخانه، ۲ گرید صریح و ۶۵ مقدار سایز اسمی. ۳ ترکیب ناسالم وارد
نمی‌شوند. ۴۲ کالا سازندهٔ مشخص‌شده ندارند. وزن، استاندارد گواهی‌شده و ابعاد نامعلوم
ساخته نشده‌اند. اسناد preparation و REVIEW-STATUS قدیمی، snapshot تاریخی پیش از
تأیید هستند؛ این گزارش وضعیت جدید را مشخص می‌کند و آن رسیدها ویرایش نشده‌اند.

نام، H1، اسلاگ، عنوان، متا، FAQ و جدول فارسی با مدل‌های موجود ذخیره می‌شوند.
کالاها و دسته‌های جدید غیرفعال‌اند؛ کالاها `inquiry` و `noindex` هستند. هیچ عکس،
قیمت، Offer یا PricingTier ساخته نمی‌شود. ماتریس ورق/رول تغییر نکرده است؛ این
قابلیت واردسازی کاتالوگ است، نه گسترش رابط ماتریس به خانواده‌های دیگر.

## مسیر اجرا در آپدیت بعدیِ مجاز

`ops/manual_deploy/update.sh` بعد از migrate و پیش از کارهای بازار، helper
`ops/manual_deploy/seed_farda_sections.sh` را با همان Python و محیط دیتابیس
آپدیتر فراخوانی می‌کند. helper ابتدا preview و سپس apply صریح با actor
`release:update.sh` دارد. خطای هر مرحله ادامهٔ آپدیت را متوقف می‌کند. هیچ خزش یا
دانلودی در seed انجام نمی‌شود؛ سایر کارهای شبکه‌ای قبلی آپدیتر تغییر نکرده‌اند.

فایل محلی: `products/data/farda_sections_v1.json`؛ دقیقاً برابر فایل بررسی‌شده.
SHA256:

```text
e9d903b8fe338bee4d72767311e9e236daf73f949280449af9fb750f19affa57
```

هش هم در service و هم helper قفل شده است؛ تغییر بسته، مجوز واردسازی نسخهٔ جدید
نیست. فایل در Git بدون تبدیل newline ذخیره می‌شود و بایت‌های archive آزموده شده‌اند.

فرمان پیش‌فرض فقط بررسی است؛ از ریشهٔ بک‌اند در محیط درست:

```sh
python manage.py seed_farda_sections --dry-run
```

تنها برای اپراتور مجاز، پس از backup و بررسی خروجی روی دیتابیس مقصد:

```sh
python manage.py seed_farda_sections --apply --actor approved-operator
```

این فرمان‌ها در این کار علیه دیتابیس واقعی اجرا نشده‌اند. برای این داده از
`loaddata`، `seed_products` یا ماتریس ورق استفاده نکنید.

## ایمنی و تکرار

preview هیچ INSERT/UPDATE/DELETE انجام نمی‌دهد. apply همهٔ ایجادها و auditها را
در یک تراکنش انجام می‌دهد. نام به‌تنهایی هویت نیست؛ دسته و مشخصات فنی و سایز
اسمی کنترل می‌شوند. تطبیق موجود بدون بازنویسی رد می‌شود؛ ابهام یا ناسازگاری
دسته/گزینه/اسلاگ/مشخصات اجرای کل بسته را متوقف می‌کند. گریدهای موجود خانوادهٔ
ورق دست‌نخورده می‌مانند؛ گزینه‌ها برای خانوادهٔ درست ساخته می‌شوند.

رسید `CATALOG_SEED_BATCH` و audit ایجادهای `CATALOG_SEED_CREATED` در
ProductAuditLog باقی می‌مانند. اجرای دوم حتی پس از تغییر اسلاگ، تکمیل مشخصات،
فعال‌کردن یا حذف محصول هیچ چیز را برنمی‌گرداند. receiptها را برای اجرای مجدد
پاک نکنید؛ receipt ناقص یا ناسازگار نیازمند بررسی دستی است. تعارض واقعی را
حل کنید، نه اینکه hash gate یا audit را دور بزنید. استثناءهای دیتابیس rollback
می‌شوند. آزمون‌های محلی SQLite هستند؛ رقابت واقعی PostgreSQL در این اجرا آزموده
نشده و این seed جایگزین هماهنگی اپراتورهای انتشار نیست.

## بررسی‌های واقعی

- ۴۲ آزمون seed و ماتریس/هویت قبلی: موفق؛ شامل apply، replay، حفظ حذف/ویرایش،
  تعارض و rollback. ثبت اولیهٔ آزمون‌ها قبل از پیاده‌سازی شکست خورد (RED).
- ۵ آزمون اجرایی helper/Bash/archive: موفق؛ شکست preview مانع apply است و
  شکست apply به فراخواننده برمی‌گردد. خود update.sh اجرا نشده است.
- کل بک‌اند: ۴۹۵ آزمون موفق در ۳۱٫۹۶۸ ثانیه، SQLite مستقل `settings_test`.
- Django check موفق؛ `makemigrations --check --dry-run` بدون تغییر؛ ۸ آزمون
  snapshot/کامپایل آفلاین و OpenSpec strict موفق.
- ۱۳ آزمون موجود سئو در فرانت‌اند موفق. مدل واقعی `buildProductSeoModel` برای
  هر ۱۴۹ ردیف: H1/متا/عنوان، noindex، نبود قیمت تازه و لینک داخلی دسته موفق.
  هیچ فایل فرانت‌اند تغییر نکرد و build کامل Next.js یا آزمون مرورگری انجام نشد.

تغییر ایمنی لازم: API قبلی محصول غیرفعال را از list حذف می‌کرد ولی retrieve
عمومی آن را برمی‌گرداند. اکنون جزئیات غیرفعال برای غیرمدیر ۴۰۴ است؛ preview
مدیر حفظ شده است. هزینهٔ سازگاری: مصرف‌کننده‌ای که عمداً به جزئیات عمومی کالای
غیرفعال تکیه کرده باشد دیگر آن را نمی‌گیرد. این تصمیم برای رعایت منتشرنشدن داده
اتخاذ شد، نه افزودن endpoint جدید.

## پس از انتشار مجاز

اپراتور خروجی seed و رسیدها را بررسی کند. مدیر در فهرست مدیریت دسته‌ها و کالاها
مشخصات، تولیدکنندهٔ نامعلوم، واحد نبشی، متن و شرایط واقعی تأمین را تأیید کند.
سپس دسته‌های لازم و محصولات انتخابی را فعال و حالت سئو را آگاهانه از noindex
تغییر دهد. seed خودش قیمت یا فروشنده تعیین نمی‌کند و رتبهٔ گوگل را تضمین نمی‌کند.
بازگشت خودکار/حذف دسته‌جمعی ارائه نشده؛ رسیدها و کالاهای ویرایش‌شده باید حفظ شوند.
