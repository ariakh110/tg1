# شروع مهندسی مشترک با Claude Code و Codex

## چه چیزی نصب شده است؟

در هر دو مخزن بک‌اند و فرانت‌اند:

- BMAD پایدار ۶٫۱۲٫۴ برای تحلیل، PRD، معماری، UX، مشخصات و توسعه؛
- Superpowers نسخه ۷٫۰٫۱ برای برنامه اجرایی، تست قبل از کد، رفع اشکال و بازبینی؛
- اسکیل رسمی `frontend-design` برای طراحی بصری و پیاده‌سازی رابط؛
- اسکیل `kaveh-engineering` برای هماهنگی این ابزارها با OpenSpec موجود.

اسکیل‌ها در `.agents/skills` برای Codex و `.claude/skills` برای Claude Code قرار دارند. فایل‌های راهنما و تصمیم‌ها در هر دو ابزار مشترک‌اند. نصب به‌صورت اسکیل محلی پروژه انجام شده؛ ثبت در Marketplace یا قلاب خودکار SessionStart انجام نشده است.

## شروع کار

۱. در Codex پروژه کاوه‌متال را باز کنید؛ برای شناسایی اسکیل‌های جدید یک گفت‌وگوی تازه در ریشه مخزن آغاز کنید. برای Claude Code نیز همان مخزن را باز کنید. اگر فرمان Claude نصب نیست، باید خود Claude Code را جداگانه نصب و وارد حساب شوید؛ این نصب، کلاینت یا اشتراک Claude را ایجاد نمی‌کند.

۲. این متن در هر دو ابزار قابل استفاده است:

> از اسکیل kaveh-engineering استفاده کن. ابتدا AGENTS.md، راهنمای docs/engineering/WORKFLOW.md، زمینه پروژه و handoff موجود را بخوان. ساختار فعلی را از روی کد بررسی کن و وضعیت واقعی را از طرح پیشنهادی جدا بنویس. برای ماژول موردنظر ابتدا قواعد کسب‌وکار، دسترسی‌ها، سناریوهای پذیرش و نمودارهای لازم را آماده کن؛ سپس طبق تأییدهای موجود به برنامه اجرایی، پیاده‌سازی، تست و بازبینی برو. خروجی‌ها را در فایل‌های پروژه ذخیره کن.

۳. برای مثال تحلیل یک ماژول:

> ماژول «استعلام خرید تا پیش‌فاکتور و سفارش» را بررسی کن. با BMAD نمودار جریان، ERD، نمودار کلاس و Sequence Diagram بساز؛ بخش موجود و پیشنهادی را مشخص کن. مسیر کاربر، وایرفریم و حالت‌های خطا و موفقیت را هم طراحی کن. فعلاً خروجی مهندسی می‌خواهم؛ کد محصول را تغییر نده.

۴. برای پیاده‌سازی طرح پذیرفته‌شده:

> براساس مشخصات و نمودارهای تأییدشده این ماژول، با Superpowers برنامه اجرایی بنویس و پیاده‌سازی کن. آزمون‌های رفتار، بررسی تطابق با مشخصات و بازبینی کیفیت و امنیت را انجام بده. اگر محیط اجازه می‌دهد از ایجنت‌های فرعی استفاده کن؛ در غیر این صورت بازبینی‌ها را ترتیبی انجام بده و این محدودیت را گزارش کن.

## نام اسکیل‌های نصب‌شده

| نیاز | اسکیل |
|---|---|
| راهنما | `bmad-help` |
| شناخت پروژه | `bmad-project-context` |
| نیازمندی محصول | `bmad-prd` |
| مشخصات و تقسیم کار | `bmad-spec` |
| معماری | `bmad-architecture` |
| تجربه کاربری | `bmad-ux` |
| طراحی رابط | `frontend-design` |
| برنامه پیاده‌سازی | `writing-plans` |
| توسعه با ایجنت‌های فرعی | `subagent-driven-development` |
| هماهنگ‌کننده جایگزین توسعه | `bmad-build` |

در Codex می‌توانید با `$kaveh-engineering` آن را انتخاب کنید. در Claude از فهرست `/` نام اسکیل را انتخاب کنید یا همان نام را در درخواست بنویسید. اسکیل‌های محلی Superpowers پیشوند افزونه `superpowers:` ندارند؛ اگر متن بالادستی به این پیشوند اشاره کرد، اسکیل هم‌نام محلی را باز کنید.

برای هر کار یک هماهنگ‌کننده توسعه انتخاب می‌شود؛ BMAD Build و گردش اجرای Superpowers داخل هم اجرا نمی‌شوند. OpenSpec بک‌اند حفظ شده و مشخصات BMAD باید به تغییر مرتبط آن لینک بدهد.

## جابه‌جایی بین دو ابزار

از ابزار فعلی بخواهید `docs/engineering/HANDOFF.md` را با الگوی موجود در `templates/HANDOFF.md` به‌روز کند. ابزار بعدی باید هدف، تصمیم‌های تأییدشده، فایل‌های تغییرکرده، نتیجه واقعی تست‌ها و قدم بعد را از همین فایل بخواند.

ChatGPT معمولی در وب به فایل‌های محلی دسترسی خودکار ندارد. برای آن، مشخصات و نمودارها و handoff را پیوست کنید؛ یا از Codex در همین workspace استفاده کنید.

## بررسی نصب

در ریشه هر مخزن:

```powershell
python docs/engineering/verify_toolchain.py --runtime
```

`uv` نسخه ۰٫۱۳٫۵ در مسیر کاربری `.local/bin` نصب شده و به PATH کاربر اضافه شده است. اگر ترمینال قدیمی آن را پیدا نکرد، ترمینال/محیط را دوباره باز کنید. نسخه‌ها و منبع دقیق در `toolchain-lock.json` ثبت‌اند.

این نصب ابزار توسعه است. ساخت یک ERP کامل، بازطراحی محصول و نصب روی سرور با این کار انجام نشده‌اند.

منابع: [BMAD](https://github.com/bmad-code-org/BMAD-METHOD)، [Superpowers](https://github.com/obra/superpowers)، [Frontend Design](https://github.com/anthropics/claude-code/tree/main/plugins/frontend-design).
