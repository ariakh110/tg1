## قواعد importer پیشنهادی

فرمان پیشنهادی `seed_farda_sections` هنوز وجود ندارد. ورودی باید فقط نسخهٔ
بازبینی‌شده و hash مشخص داشته باشد؛ هیچ شبکه‌ای هنگام seed یا deploy لازم نیست.
پیش‌فرض preview بدون نوشتن، apply صریح در تراکنش اتمیک، و ایجاد اولیهٔ غیرفعال است.
ساخت دسته/گزینه با کد و دامنهٔ دقیق؛ برخورد نام یکتا یا چند تطبیق = گزارش تعارض، نه تغییر دستهٔ موجود.
محصول موجود از طریق هویت فنی/اسلاگ و audit seed شناسایی و دست‌نخورده رد می‌شود؛
تغییر نام یا غیرفعال‌سازی مدیر نباید در اجرای بعد برگردد. حذف دستی نیز از audit مشخص و خودکار بازسازی نمی‌شود.
تنها ایجادها ProductAuditLog با batch hash و key می‌گیرند؛ actor باید مشخص باشد.

## وضعیت UX و API

در این مرحله UI یا API جدیدی ساخته نمی‌شود. مدیریت دسته و نوع سفارشی از قبل وجود دارد؛
ماتریس محصول صریحاً sheet-only است و این seed مستقل از آن طراحی می‌شود.
صفحهٔ خانواده از نام دسته metadata و breadcrumb می‌سازد؛ صفحهٔ محصول overrideهای سئو را می‌خواند.
عنوان و جدول اختصاصی محتوای محصول برای سایز اسمی و هر دو بال لازم‌اند؛ جدول عمومی فعلی ارتفاع را نمایش نمی‌دهد.
فعال‌سازی محصولات/والدها و تغییر index پس از تأیید مشخصات و بررسی خروجی SSR است، نه صرف تکمیل فایل JSON.
