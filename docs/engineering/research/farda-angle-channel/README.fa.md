# بستهٔ بررسی نبشی و ناودانی فردا فولاد

تاریخ برداشت: ۵ نوامبر ۲۰۲۶. پروژهٔ مقصد: بک‌اند کاوه‌متال، نه Unity.
وضعیت: **داده و طرح آمادهٔ بررسی؛ importer و اتصال به آپدیت هنوز پیاده نشده‌اند.**
این JSON فایل fixture جنگو نیست و نباید با `loaddata` یا seed نمونهٔ فعلی اجرا شود.

## خروجی

| گروه | کالای یکتا |
| --- | ---: |
| نبشی ساختمانی | ۷۰ |
| نبشی ST52 | ۵ |
| نبشی 5SP | ۹ |
| ناودانی ساختمانی | ۳۷ |
| ناودانی گروه اروپا | ۱۹ |
| ناودانی هم‌وزن اروپا | ۹ |
| مجموع پیشنهادی | ۱۴۹ |

۴۶۷ مشاهده از ۱۱ صفحه بررسی شده است؛ ۴۶۱ مشاهده به کالاهای پیشنهادی و ۶ مشاهده
به ۳ ترکیب قرنطینه‌شده تعلق دارند. تکرار یک کالا در کارخانه/انبار یا صفحهٔ مادر/فرزند
محصول جدید نیست. منبع هر مشاهده، عنوان جدول، شماره ردیف و دادهٔ خام حفظ شده‌اند.
برای ناودانی آریان فولاد صفحهٔ معرفی بدون جدول سایزبندی مشاهده شد؛ هیچ سایزی از روی حدس ساخته نشد.
سپری، میلگرد، ورق و دیگر خانواده‌ها خارج از محدوده‌اند.

## فایل‌ها

- `products-review.csv`: فهرست قابل بررسی در اکسل؛ UTF-8 با BOM. برای import فعلی ادمین نیست.
- `seed-candidate.json`: دادهٔ پیشنهادی شامل ۸ دسته، ۱۶ گزینهٔ کارخانه، ۲ گرید و ۱۴۹ کالا؛ روابط با کد، نه ID دیتابیس.
- `source-catalog.json`: جدول‌های فنی منبع، URL، تاریخ برداشت و hash محتوای دریافتی؛ بدون قیمت، تصویر، متن تبلیغاتی یا مخاطبان.
- `quarantine-review.csv`: سه ترکیب خراب با شش مشاهده؛ داخل JSON نیز حفظ شده‌اند.
- `collect_catalog.py`: دریافت خواندنی جداول عمومی؛ برنامهٔ seed نیست.
- `prepare_seed.py`: تولید کاندیدا از snapshot آفلاین روی stdout، بدون دیتابیس.
- `test_catalog.py`: آزمون آفلاین دامنه، منشأ، تکراری‌ها، اعشار، قرنطینه، گرید و بازتولیدپذیری.
- `validate_models.py`: بررسی نام، نوع، محدودیت طول و choices با مدل‌های فعلی؛ نه آزمون import/روابط در دیتابیس.

## چه چیزهایی خودکار آماده شده‌اند؟

نام، اسلاگ پایدار، خانواده/زیرگروه، مشخصات موجود در منبع، عنوان و متای سئو، H1،
توضیح کوتاه، جدول HTML تألیفی و FAQ. canonical به مسیر محصول روی **دامنهٔ خود سایت** اشاره می‌کند.
خانواده‌های angle و channel مستقل از sheet هستند. صفحات دستهٔ فعلی سایت نام دسته را برای metadata می‌خوانند؛
مدل ProductCategory فیلد مستقل seo_title ندارد و فیلد خیالی برای آن ایجاد نشده است.
این داده به‌تنهایی نه ساخت صفحات در سایت را اجرا می‌کند و نه تضمینی برای رتبه یا rich result است.

## اطلاعاتی که جعل یا کپی نشده‌اند

قیمت، موجودی، فروشنده، محل تحویل متعلق به خود فروشگاه، عکس‌های منبع، وزن،
گواهینامه، استاندارد DIN/EN، گرید ST37 و ابعاد اعلام‌نشده وارد نشده‌اند.
ST52 و 5SP فقط برای همان ۱۴ ردیفِ صریح منبع ذخیره می‌شوند؛ این‌ها گریدند، نه گواهینامهٔ استاندارد.
۴۲ کالا سازندهٔ شناسایی‌شده ندارند: ۲۸ ناودانی گروه‌های اروپایی و ۱۴ نبشی گریددار.
«انبار تهران» در ستون برند به کارخانه تبدیل نشده است. درج «اروپا» نیز اثبات کشور سازنده نیست.

سایز اسمی ناودانی در مشخصات داینامیک می‌ماند؛ مثلاً ۶/۵ به ۶٫۵ تبدیل می‌شود،
اما بدون مدرک به ارتفاع ۶۵ میلی‌متر یا وزن قطعی تبدیل نمی‌شود.
تبدیل اندازهٔ بال و ضخامت نبشی به میلی‌متر یک فرض متعارفِ مستند است که قبل از apply باید تأیید شود.

## موارد قرنطینه

- ناودانی ساختمانی ماهان، سایز ۱۲، کارخانه: واحد «۶ متری» به‌جای واحد وزن.
- ناودانی هم‌وزن اروپا، سایز ۲۶: واحد «۱۲ متری».
- ناودانی هم‌وزن اروپا، سایز ۲۸: حالت «انبار تهران» و واحد «۱۲ متری».

اصلاح دستی بی‌مدرک انجام نشده است؛ برای ساخت این سه مورد به تأیید طول و واحد نیاز است.

## اجرای دوبارهٔ بررسی‌ها، از ریشهٔ بک‌اند

```powershell
& .venv/Scripts/python.exe -X utf8 -m unittest discover -s docs/engineering/research/farda-angle-channel -p test_catalog.py -v
& .venv/Scripts/python.exe docs/engineering/research/farda-angle-channel/validate_models.py
& .venv/Scripts/python.exe manage.py check --settings=tg1.settings_test
```

۸ آزمون داده، بررسی فیلدهای ۱۴۹ کالا/۸ دسته/۱۸ گزینه، و Django check گذشتند.
آزمون importer اتمیک، اجرای مجدد روی دیتابیس، روابط و hook انتشار هنوز اجرا نشده‌اند چون importer ساخته نشده است.

## قدم بعد از تأیید

طرح در `openspec/changes/add-angle-channel-catalog-seed/` و قرارداد BMAD در
`docs/engineering/bmad-output/specs/spec-angle-channel-catalog-seed/` است.
فرمان پیشنهادی `seed_farda_sections` باید با dry-run پیش‌فرض، apply صریح و اتمیک،
عدم بازنویسی، تشخیص تعارض و audit ساخته و روی دیتابیس تست آزموده شود.
سپس فقط بستهٔ local نسخه‌دار در ورودی کنترل‌شدهٔ آپدیت فراخوانی می‌شود؛ خزش زنده زمان deploy نخواهد داشت.
برای ابتدا Product و دسته‌ها غیرفعال، وضعیت inquiry و SEO روی noindex پیشنهاد شده است؛
فعال‌سازی و index پس از تأیید مشخصات و بررسی صفحهٔ SSR انجام می‌شود.

محدودیت ماتریس فعلی همچنان پابرجاست؛ این بسته مستقل از ماتریس طراحی شده و پشتیبانی
ماتریسی همهٔ دسته‌ها یا حتی نبشی/ناودانی را پیاده‌سازی‌شده اعلام نمی‌کند.
