# ارسال گزارش‌های سایت با ربات فعلی گوگل‌شیت

مسیر: پنل سایت ← تأیید انتشار گزارش بورس ← صف خصوصی سایت ← Google Apps Script ← ربات فعلی تلگرام ← کانال.

سایت در این حالت مستقیماً به تلگرام متصل نمی‌شود. توکن ربات در Script Properties گوگل باقی می‌ماند. سایت فقط هش کلید اتصال جداگانه را نگه می‌دارد. کلید اتصال ربات تلگرام نیست و نباید توکن BotFather را در آن وارد کنید.

## ۱. نصب نسخه سایت

هر سه فایل جدید `backend.tar.gz`، `frontend.tar.gz` و `update.sh` از `C:\Users\aria\deploy` را در `/home/deploy/kavehmetal-release/` بارگذاری کنید. در PuTTY:

```bash
sudo bash <<'DEPLOY'
set -euo pipefail
install -m0644 /home/deploy/kavehmetal-release/backend.tar.gz /srv/tirexa/backend.tar.gz
install -m0644 /home/deploy/kavehmetal-release/frontend.tar.gz /srv/tirexa/frontend.tar.gz
install -m0755 /home/deploy/kavehmetal-release/update.sh /srv/tirexa/update.sh
env APP_ROOT=/srv/tirexa bash /srv/tirexa/update.sh both
DEPLOY
```

این تغییر شامل migration پیام‌رسانی 0012 است. صرفاً تعویض کد گوگل بدون نصب نسخه سایت کافی نیست.

## ۲. جایگزینی کد ربات گوگل

فایل کامل آماده: `ops/google_relay/KavexChannelBot.private.gs` در بسته بک‌اند؛ همان فایل در پوشه `my learner` نیز آماده شده است.

۱. گوگل‌شیت همان ربات فعلی را باز کنید و `Extensions → Apps Script` را بزنید.
۲. کل محتوای فایل آماده را جایگزین `Code.gs` کنید و ذخیره کنید؛ به انتهای کد قبلی اضافه نکنید. نسخه جدید ۱.۲.۰ است و قابلیت‌های قبلی ربات را دارد.
۳. تابع `refreshKavexMenus` را اجرا کنید و شیت را دوباره باز کنید. دسترسی‌های گوگل را در صورت درخواست تأیید کنید.
۴. توکن و مدیر قبلی در Script Properties باقی می‌مانند. برای رباتی که قبلاً کار می‌کرد نیازی به ثبت دوباره توکن، نصب دوباره شیت‌ها یا تغییر Webhook نیست.

## ۳. اتصال سایت و گوگل

۱. در سایت: پنل مدیریت ← پیام‌رسانی ← «پیام‌های آماده بورس» ← روش اتصال تلگرام.
۲. مسیر «ربات گوگل‌شیت (دریافت از صف سایت)» را انتخاب کنید.
۳. شناسه مقصد کانال را درست وارد کنید. اگر مقصد قبلی ربات شما `@kavexir` است، همان را در سایت بگذارید و لینک امضای کانال را نیز هماهنگ کنید. ربات باید در همین کانال مدیر و دارای اجازه انتشار باشد.
۴. «ساخت کلید جدید» و سپس «کپی کلید برای گوگل» را بزنید؛ کلید را پیش از ذخیره کپی کنید. سپس «ذخیره تنظیمات کانال‌ها» را بزنید. پس از ذخیره، مقدار کلید از سایت قابل خواندن نیست؛ ساخت کلید تازه اتصال قبلی را غیرفعال می‌کند.
۵. در منوی شیت «تنظیم اتصال سایت» را اجرا کنید و به ترتیب این مقادیر را وارد کنید:
   - آدرس اصلی: `https://kavehmetal.com` بدون `/api` یا مسیر دیگر؛
   - همان کلید اتصال کپی‌شده؛
   - دقیقاً همان شناسه کانال ثبت‌شده در سایت.
۶. در شیت «فعال‌سازی دریافت پیام‌های سایت» را اجرا کنید. این زمان‌بند از دریافت تلگرام و انتشار صبحگاهی مستقل است. Web App یا Deployment عمومی گوگل لازم نیست.

## ۴. آزمایش با یک پیام واقعی به انتخاب شما

۱. در پنل سایت تاریخ دارای معامله را انتخاب کنید و پیش‌نمایش بسازید؛ این کار هنوز پیامی ارسال نمی‌کند.
۲. متن را بررسی و فقط یک پیام را برای تلگرام تأیید کنید. وضعیت باید «در صف گوگل» باشد.
۳. حدود یک دقیقه منتظر بمانید یا در شیت «دریافت پیام‌های سایت همین حالا» را اجرا کنید. این گزینه واقعاً پیام‌های تأییدشده صف را ارسال می‌کند.
۴. کانال را بررسی کنید. سایت پس از رسید گوگل، وضعیت «ارسال شد» را نشان می‌دهد. تا وقتی صفحه باز است، وضعیت صف هر ۱۵ ثانیه تازه می‌شود.
۵. هر اجرای گوگل حداکثر سه پیام برمی‌دارد. برای صف بزرگ‌تر چند اجرای زمان‌بند لازم است.

## قطع ارتباط و جلوگیری از تکرار

- قطع ارتباط در ثبت رسید: گوگل فقط ثبت همان رسید را تکرار می‌کند و پیام تلگرام دوباره فرستاده نمی‌شود.
- توقف نامشخص پس از شروع ارسال: تلاش با وضعیت نامشخص نگه داشته می‌شود. دریافت دوبارهٔ خودکار پیام انجام نمی‌شود.
- دریافت پیام از سایت و توقف گوگل قبل از ثبت نتیجه: بعد از ده دقیقه، سایت نتیجه را نامشخص نشان می‌دهد؛ پیام خودکار به صف ارسال برنمی‌گردد.
- برای تلاش دوباره در حالت نامشخص، ابتدا کانال را شخصاً بررسی کنید و تنها در صورت منتشر نشدن، از دکمه تأیید بررسی و سپس تلاش دوباره استفاده کنید. این دکمه مجوز تلاش تازه است و تأیید تحویل نیست.
- اگر حالت دریافت خودکار ربات گوگل را متوقف کنید، پیام‌های تأییدشده در صف سایت می‌مانند. برای توقف دریافت سایت، گزینه مستقل «توقف دریافت پیام‌های سایت» را اجرا کنید.

در سایت «بررسی زمان آخرین دریافت گوگل» و در شیت «وضعیت اتصال سایت» برای عیب‌یابی موجود است. آدرس غیر HTTPS، تغییرمسیر HTTP، کلید نادرست و مقصد متفاوت پذیرفته نمی‌شوند. اگر سایت از شبکه گوگل قابل دسترسی نباشد یا Bot API تلگرام درخواست را رد کند، ارسال واقعی انجام یا تأیید نمی‌شود.

## دامنه و اعتبارسنجی

این اتصال برای گزارش‌های تأییدشدهٔ بخش «پیام‌های آماده بورس» سایت است. پیامک، بله و اعلان‌های داخلی سایت از مسیر فعلی خودشان استفاده می‌کنند. در زمان توسعه هیچ پیام واقعی به کانال ارسال نشد و کد روی حساب گوگل شما نصب نشد؛ این دو کار پس از مراحل بالا انجام می‌شوند.

منابع فنی: [درخواست HTTPS از گوگل](https://developers.google.com/apps-script/reference/url-fetch/url-fetch-app)، [زمان‌بندهای نصب‌شدنی گوگل](https://developers.google.com/apps-script/guides/triggers/installable).

## شواهد اعتبارسنجی محلی

- ۳۶۲ تست بک‌اند موفق، شامل احراز هویت، کلید فقط‌نوشتنی و هش‌شده، صف تکرارناپذیر، دریافت یک‌باره، رسید تکرارپذیر، پایان تلاش نامشخص و تلاش تازه پس از بررسی مدیر.
- ۳۷ تست frontend و lint فایل‌های تغییرکرده و ساخت نهایی Next.js موفق.
- تست مرورگر با API شبیه‌سازی‌شده: ذخیره مسیر گوگل، پاک‌شدن نمایش کلید بعد از ذخیره، صف چندپیامی و تغییر وضعیت از رسید بدون انتشار مجدد موفق.
- ۱۸ تست قبلی ربات خصوصی و ۶ تست اتصال گوگل و هماهنگی فایل کامل با ماژول موفق.
- ابزار استاندارد trace برای بدنه توابع API واسط: ۵۸/۵۸ خط اجرا شد؛ این پوشش خطی همان فایل است، نه پوشش شاخه‌ها یا کل پروژه.
- دسترسی واقعی از گوگل به سایت و تلگرام، پس از نصب در حساب مالک باید با یک پیام انتخابی بررسی شود.

## فقط کالاهای معامله‌شده در گزارش

در «پیام‌های آماده بورس» و بخش «ساخت پیام‌های آماده»، گزینه «فقط کالاهای معامله‌شده» را روشن کنید و پیش‌نمایش بسازید. تنها ردیف‌های با حجم معامله بیشتر از صفر وارد پیام تفکیکی یا محاسبات خلاصه گروه می‌شوند. حجم صفر، نامشخص یا منفی حذف می‌شود. گزینه به‌صورت پیش‌فرض خاموش است. با تغییر آن پیش‌نمایش و انتخاب‌های قبلی پاک می‌شوند تا گزارش با فیلتر جدید ساخته شود. این فیلتر مخصوص ایجاد گزارش است.
