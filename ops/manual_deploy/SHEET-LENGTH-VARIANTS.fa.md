# ثبت مستقل ورق با طول ثابت و «به طول»

تاریخ: ۲۰۲۶/۱۰/۲۴. کد و بستهٔ دیپلوی آماده شده‌اند؛ اعمال روی سرور با WinSCP/PuTTY انجام می‌شود.

## مشکل و اصلاح

قبلاً تشخیص محصول موجود فقط بر اساس نام و دسته بود و `.first()` اولین رکورد را انتخاب می‌کرد. در نتیجه ثبت محصول هم‌نام با طول متفاوت می‌توانست مشخصات و قیمت قبلی را بازنویسی کند؛ رکورد لزوماً حذف نمی‌شد.

اکنون مشخصات ارسال‌شده، شامل طول، نوع طول، ضخامت، عرض، کارخانه و گرید، در تطبیق بررسی می‌شوند. اگر چند محصول مطابق باقی بمانند، درخواست مبهم رد می‌شود و باید محصول را برای ویرایش با شناسه انتخاب کرد. ویرایش صریح با شناسه همچنان همان رکورد را تغییر می‌دهد. این رفتار برای فرم ادمین و مسیر مشترک واردکردن فایل اعمال می‌شود.

## ثبت مثال کاویان ۳۰ میل

هر دو را به‌عنوان محصول جدید با قیمت مستقل ثبت کنید:

| کالا | نوع طول | مقدار طول در فرم |
|---|---|---|
| ورق ۶ متری | طول ثابت | `6000` میلی‌متر |
| ورق به طولِ بالای ۷ متر | به طول؛ بیش از مقدار واردشده | `7000` میلی‌متر |

«بیش از ۷ متر» یک حد پایین است، نه طول دقیق. نمایش عمومی و جدول مشخصات این تفاوت را نشان می‌دهند. بدون ابعاد دقیقِ شرط قیمت یا وزن واحدِ صریح، وزن هر ورق و تعداد ورق از این حد پایین تخمین زده نمی‌شود؛ ورق به طول را بر حسب کیلوگرم/تن سفارش دهید. مسیر درخواست مستقیمِ برش نیز برای این نوع کالا از محاسبهٔ خودکار با طول نامعین جلوگیری می‌کند.

محصولات قبلی در migration نوع طول `fixed` می‌گیرند. این اصلاح رکوردهایی را که قبلاً بازنویسی شده‌اند بازیابی نمی‌کند؛ آن موارد را پس از دیپلوی بررسی و دوباره ثبت کنید.

## اعتبارسنجی

- تست‌های بازتولید قبل از اصلاح شکست خوردند و checkpointهای آن‌ها در Git ثبت شدند.
- تست API: حفظ قیمت و مشخصات دو طول، تمایز طول ثابت و حد پایین یکسان، واردکردن قیمت برای نوع درست، رد نام مبهم، حفظ ویرایش با شناسه، پیش‌فرض دسته و جلوگیری از وزن نامعتبر.
- ۳۲۸ تست بک‌اند و ۳۴ تست فرانت‌اند موفق؛ production build موفق.
- تست مرورگر با API ساختگی: انتخاب نوع طول، ذخیرهٔ مقدار 7000، بازکردن مجدد ویرایش و حفظ صفحه‌بندی/فیلترها موفق. این تست مرورگر روی سرور اصلی اجرا نشده است.
- audit وابستگی‌های اجرایی فرانت‌اند: صفر هشدار در زمان بررسی.
- migration جدید: `products.0023_productspecification_length_type`. بک‌اند و فرانت‌اند باید با هم دیپلوی شوند.

## دیپلوی

پس از بکاپ دیتابیس، سه فایل جدید در `C:\Users\aria\deploy` را با WinSCP در `/home/deploy/kavehmetal-release/` جایگزین کنید: `backend.tar.gz`، `frontend.tar.gz` و `update.sh`.

در PuTTY با کاربر deploy اجرا کنید:

```bash
sudo bash <<'DEPLOY'
set -euo pipefail
install -m0644 /home/deploy/kavehmetal-release/backend.tar.gz /srv/tirexa/backend.tar.gz
install -m0644 /home/deploy/kavehmetal-release/frontend.tar.gz /srv/tirexa/frontend.tar.gz
install -m0755 /home/deploy/kavehmetal-release/update.sh /srv/tirexa/update.sh
env APP_ROOT=/srv/tirexa bash /srv/tirexa/update.sh both
DEPLOY
```

اسکریپت migration را هم اجرا می‌کند. پس از پایان موفق، دو محصول نمونه را ثبت کنید و مستقل‌ماندن قیمت هر دو را در لیست بررسی کنید.
