# دکمه چسبان استعلام خرید با تأیید پیامکی

## امکانات

- دکمه «استعلام خرید» پایین سمت راست صفحات عمومی؛ در موبایل بالاتر از نوار پایین و جدا از گفت‌وگوی فروش قرار دارد.
- پنجرهٔ بازشونده با انتخاب ورق سیاه یا میلگرد، ضخامت/سایز به میلی‌متر، مقدار به کیلوگرم، شهر تحویل و نام اختیاری و موبایل.
- پیشنهاد سایز از مشخصات کاتالوگ فعال دریافت می‌شود؛ واردکردن سایز دیگر هم ممکن است.
- کاربر بدون ورود به حساب، کد پیامکی می‌گیرد و بعد از تأیید موبایل، استعلام ثبت می‌شود. فرم به فعال‌بودن دستیار هوش مصنوعی وابسته نیست.
- پس از ثبت، کد پیگیری نمایش داده می‌شود. درخواست در استعلام‌های پنل دستیار فروش و جریان فرصت‌های CRM دیده می‌شود؛ نام/اطلاعات قبلی مشتری با ارسال فرم بازنویسی نمی‌شود.
- دکمه در پنل مدیریت، حساب کاربر، سبد، تسویه و صفحات ورود نمایش داده نمی‌شود.

## نصب نسخه سایت

هر سه فایل جدید `backend.tar.gz`، `frontend.tar.gz` و `update.sh` از `C:\Users\aria\deploy` در `/home/deploy/kavehmetal-release/` بارگذاری شوند. سپس در PuTTY:

```bash
sudo bash <<'DEPLOY'
set -euo pipefail
install -m0644 /home/deploy/kavehmetal-release/backend.tar.gz /srv/tirexa/backend.tar.gz
install -m0644 /home/deploy/kavehmetal-release/frontend.tar.gz /srv/tirexa/frontend.tar.gz
install -m0755 /home/deploy/kavehmetal-release/update.sh /srv/tirexa/update.sh
env APP_ROOT=/srv/tirexa bash /srv/tirexa/update.sh both
DEPLOY
```

Migrationهای `assistant/0005` و `messaging/0013` باید اعمال شوند؛ نصب‌کننده این کار را انجام می‌دهد.

## فعال‌سازی پیامک

۱. پنل مدیریت ← پیام‌رسانی ← تنظیمات پنل.
۲. ارسال پیامک را فعال و کلید معتبر کاوه‌نگار و خط ارسال را مطابق حساب خود ذخیره کنید. حساب ارائه‌دهنده باید اعتبار و اجازه ارسال داشته باشد.
۳. برای کد تأیید، فیلد جداگانهٔ «الگوی کد تأیید استعلام خرید» اضافه شده است. نام یک الگوی تأییدشده با یک پارامتر `token` برای کد را وارد کنید. خالی بودن فیلد، ارسال متن ساده با خط حساب را انتخاب می‌کند؛ رسیدن پیامک متنی به محدودیت‌های خط/گیرنده وابسته است.
۴. سقف روزانهٔ پیامک پنل برای این ارسال‌ها هم بررسی می‌شود. علاوه بر آن، سقف مستقل این قابلیت به‌صورت پیش‌فرض ۲۰۰ پیامک در روز است؛ مقدار `PURCHASE_INQUIRY_SMS_DAILY_LIMIT` در محیط backend آن را تغییر می‌دهد. برای تغییر محیط، سرویس backend باید راه‌اندازی مجدد شود.
۵. Redis مربوط به کش `authentication` باید فعال باشد؛ در صورت قطع آن، ارسال کد متوقف می‌شود.

در توسعه هیچ پیامک واقعی ارسال نشده است. بعد از نصب و تنظیمات، مسیر را با شمارهٔ متعلق به خودتان و یک درخواست انتخابی آزمایش کنید. هزینه پیامک طبق حساب ارائه‌دهنده است.

## رفتار کد و ثبت

- اعتبار کد: پنج دقیقه؛ حداکثر پنج ورود اشتباه برای هر کد.
- فاصله ارسال مجدد: حداقل ۶۰ ثانیه؛ حداکثر سه پیامک برای هر شماره در ساعت و ده پیامک در روز، همراه محدودیت IP و سقف سراسری.
- فقط هش کد نگهداری می‌شود؛ متن کد در گزارش ارسال پیامک و پاسخ API نمایش داده نمی‌شود.
- تلاش مجدد همان درخواست، پیامک یا استعلام تکراری نمی‌سازد. ورود کد صحیح پس از ثبت، همان کد پیگیری را برمی‌گرداند.
- مشخصات استعلام در مرحله دریافت کد ثابت می‌شوند؛ تغییر کالا، مقدار یا شماره، نیازمند درخواست تأیید مربوط به همان مشخصات است.
- تنظیمات یا اتصال پیامک نامعتبر با پیام خطا مشخص می‌شود؛ بدون تأیید، استعلام فروش ایجاد نمی‌شود.

این قابلیت، دریافت و پیگیری استعلام است؛ قیمت یا پیش‌فاکتور نهایی توسط کارشناس بررسی می‌شود.

## اعتبارسنجی نسخه

- ۳۷۴ تست بک‌اند و ۳۹ تست frontend موفق؛ بررسی Django، نبود migration تولیدنشده، lint فایل‌های تغییرکرده و ساخت نهایی Next.js موفق.
- بررسی مرورگر با API شبیه‌سازی‌شده: دکمه ثابت، عدم تداخل موبایل، انتخاب محصول، اعداد فارسی، کد اشتباه و صحیح، کد پیگیری و مخفی‌بودن دکمه در صفحه ورود موفق.
- حرکت Tab داخل پنجره، بستن با Escape و برگشت فوکوس به دکمه بررسی شد. نمایش دسکتاپ و موبایل نیز بازبینی شد.
- اجرای ۹ تست اختصاصی با ابزار trace پایتون، ۱۰۶ از ۱۱۹ خط اجرایی بدنه توابع `assistant/purchase_inquiries.py` را پوشش داد (۸۹٫۱٪)؛ این عدد پوشش شاخه‌ها یا کل پروژه نیست.
- نصب روی سرور و تحویل واقعی پیامک هنوز انجام نشده است؛ این دو مرحله به نصب نسخه و تنظیم حساب پیامک مالک وابسته‌اند.
