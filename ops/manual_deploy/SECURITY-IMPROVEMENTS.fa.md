# بهبودهای امنیتی کاوه‌متال با ECC

تاریخ: ۲۰۲۶/۱۰/۲۲. دامنه: پنج یافتهٔ تأییدشدهٔ ممیزی قبلی و وابستگی‌های آسیب‌پذیر. تغییرات روی کد و محیط محلی انجام شد؛ سرور اصلی دیپلوی نشده است.

## ۱. اسناد و مشخصات محصولات
- ایجاد مشخصات فقط برای ادمین یا فروشنده‌ای مجاز است که روی همان محصول پیشنهاد فروش دارد.
- ویرایش مشخصات فروشندهٔ مجاز دوباره کار می‌کند؛ مجوز قبلی اشتباهاً مالک مدل Seller را بررسی می‌کرد.
- جابه‌جایی سند یا مشخصات به محصول دیگر رد می‌شود.
- اسناد فقط PDF، DWG و DXF با پسوند و امضای سازگار و حداکثر ۱۰ مگابایت پذیرفته می‌شوند. HTML، SVG، فایل خالی، فایل با پسوند جعلی و فایل بزرگ رد می‌شوند.
- بررسی امضا جایگزین اسکن بدافزار یا بررسی کامل ساختار PDF/CAD نیست. فایل‌های قدیمی حذف یا جست‌وجو نشده‌اند؛ نحوهٔ سرو فایل‌های media توسط Nginx در سرور بررسی نشده است.

## ۲. HTML لندینگ‌ها
- پاک‌سازی هنگام ذخیره و پاسخ API اعمال می‌شود؛ متن، تصویر، جدول و قالب‌بندی مجاز باقی می‌مانند.
- migration شمارهٔ `blog.0013` محتوای قبلی را نیز پاک‌سازی می‌کند و تکرار آن بی‌اثر است.
- برگرداندن migration کدهای اجرایی حذف‌شده را بازنمی‌گرداند؛ پیش از دیپلوی از دیتابیس بکاپ بگیرید.

## ۳. محدودسازی دستیار فروش
- پیش‌فرض: ۱۰ درخواست در دقیقه و ۱۰۰ درخواست در روز برای هر IP؛ برای کاربر واردشده، سهمیهٔ کاربر نیز هم‌زمان بررسی می‌شود.
- تغییر session_key، ورود به حساب یا عوض‌کردن IP کاربر واردشده سهمیهٔ قبلی را دور نمی‌زند.
- شمارنده‌ها در کش `authentication` هستند؛ در production همان Redis موجود استفاده می‌شود. به Redis یا سرویس جدید نیاز نیست، اما اتصال فعلی باید سالم باشد.
- اتمام سهمیه: HTTP 429 همراه Retry-After. خطای کش: HTTP 503 بدون تماس با مدل.
- سهمیه‌ها پنجرهٔ ثابت دارند؛ نزدیک مرز یک دقیقه می‌توانند تا دو برابر سقف دقیقه‌ای اجازه دهند. این کنترل سقف مبلغ دلاری یا محدودسازی حملهٔ توزیع‌شده نیست.
- برای تنظیم در محیط سرور:

```dotenv
ASSISTANT_CHAT_MINUTE_LIMIT=10
ASSISTANT_CHAT_DAILY_LIMIT=100
```

پس از تغییر محیط سرویس، آن را restart کنید. Gunicorn باید فقط پشت Nginx باشد و Nginx باید X-Forwarded-For را با IP واقعی بازنویسی کند؛ همان قرارداد موجود settings_production حفظ شده است.

## ۵. نتیجهٔ بررسی‌ها
- پنج تست اولیه قبل از اصلاح شکست خوردند و یافته‌ها را بازتولید کردند؛ checkpoint تست‌ها در Git ثبت شد.
- پس از اصلاح و ارتقای بسته‌ها: ۳۱۷ تست بک‌اند موفق، شامل ۱۵ تست مربوط به اصلاحات امنیتی.
- ۲۶ تست فرانت‌اند موفق؛ کد فرانت‌اند در این تغییرات عوض نشد.
- پوشش خطی سه ماژول `assistant/throttles.py`، `products/document_validation.py` و `blog/content_sanitizer.py` با tracer داخلی Python در تست‌های هدفمند: ۱۰۰٪. این عدد پوشش کل پروژه یا پوشش شاخه‌ها نیست.
- `makemigrations --check --dry-run`: تغییری جا نمانده است.
- `check --deploy --tag security` با محیط ساختگی production: بدون خطا، دو هشدار قبلی HSTS دربارهٔ subdomain/preload باقی ماندند؛ فعال‌کردنشان نیاز به بررسی همهٔ زیردامنه‌ها دارد.
- npm audit محیط اجرا: صفر هشدار. پنج گزارش high در ابزارهای توسعه باقی مانده‌اند که همگی به زنجیرهٔ ESLint → fast-glob → micromatch → braces مربوط‌اند؛ نسخهٔ اصلاح‌شده برای braces در گزارش موجود نیست. downgrade ناسازگار Next/ESLint یا audit fix --force اجرا نشد.
- تست‌ها از دیتابیس و media موقت استفاده کردند. پیام واقعی تلگرام/بله یا درخواست واقعی مدل ارسال نشد.
- تست Redis واقعی روی سرور، مرور کامل سابقهٔ Git و تست نفوذ سرور جزو این اجرا نبودند.

## دیپلوی با WinSCP و PuTTY

ابتدا بکاپ دیتابیس و فایل‌ها را طبق روش بکاپ سرور بگیرید. سه فایل `backend.tar.gz`، `frontend.tar.gz` و `update.sh` آماده‌شده در `C:\Users\aria\deploy` را با WinSCP در `/home/deploy/kavehmetal-release/` جایگزین کنید.

سپس با کاربر deploy در PuTTY اجرا کنید:

```bash
sudo bash <<'DEPLOY'
set -euo pipefail
install -m0644 /home/deploy/kavehmetal-release/backend.tar.gz /srv/tirexa/backend.tar.gz
install -m0644 /home/deploy/kavehmetal-release/frontend.tar.gz /srv/tirexa/frontend.tar.gz
install -m0755 /home/deploy/kavehmetal-release/update.sh /srv/tirexa/update.sh
env APP_ROOT=/srv/tirexa bash /srv/tirexa/update.sh both
DEPLOY
```

اسکریپت وابستگی‌های سرور را نصب و migration را اعمال می‌کند. اگر pip در سرور هم مشکل شبکه داشت، تا نصب موفق وابستگی‌ها و پایان موفق اسکریپت، دیپلوی را موفق حساب نکنید.

پس از دیپلوی، سلامت سرویس‌ها را بررسی کنید و در مرورگر ذخیرهٔ مشخصات محصول خود، ذخیرهٔ لندینگ و یک درخواست عادی دستیار را امتحان کنید. نیاز به ارسال دسته‌ای پیام برای بررسی این اصلاحات نیست.
