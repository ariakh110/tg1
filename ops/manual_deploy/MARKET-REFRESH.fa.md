# به‌روزرسانی بورس کالا و فلزات جهانی

## رفتار نسخه جدید

- تنظیمات سایت ← بورس کالای ایران: دریافت خودکار یا دستی؛ پیش‌فرض هر ۳۰ دقیقه، قابل تنظیم از ۵ تا ۱۴۴۰ دقیقه. دکمه «ذخیره و دریافت الآن بورس کالا» مستقل از حالت خودکار است.
- تنظیمات سایت ← بازار جهانی فلزات: فعال‌بودن منبع و حالت دریافت خودکار جدا هستند. فاصله دریافت فعلی حفظ می‌شود (پیش‌فرض ۲۰ ساعت). کلید معتبر Metals.Dev باید در پنل ثبت شود؛ کلید در پاسخ API نمایش داده نمی‌شود.
- صفحه‌های عمومی هر دقیقه داده ذخیره‌شده سرور را تازه می‌کنند. این کار باعث تماس مستقیم بازدیدکنندگان با ارائه‌دهنده نمی‌شود.
- بورس کالا انتخاب روز دارد. نقشه، جمع‌ها و جدول متعلق به همان روز هستند. روز بدون داده خالی نمایش داده می‌شود و چهارشنبه به اسم امروز نمایش داده نمی‌شود.
- زمان آخرین دریافت موفق با تاریخ واقعی معامله یا قیمت فرق دارد. تعطیلی یا تأخیر انتشار منبع، تاریخ داده را جلو نمی‌برد. خطا، داده موفق قبلی را حذف نمی‌کند.
- دریافت‌های زمان‌بند و پنل با قفل موقت دیتابیس از هم‌پوشانی محافظت می‌شوند. فاصله تنظیمی برای تلاش ناموفق هم رعایت می‌شود.

## نصب

هر دو بسته backend و frontend به همراه update.sh جدید لازم هستند؛ نسخه جدید شامل migrationهای core/0009 و products/0024 است.
فایل‌های `C:\Users\aria\deploy` را با WinSCP در `/home/deploy/kavehmetal-release/` جایگزین کنید، سپس در PuTTY:

```bash
sudo bash <<'DEPLOY'
set -euo pipefail
install -m0644 /home/deploy/kavehmetal-release/backend.tar.gz /srv/tirexa/backend.tar.gz
install -m0644 /home/deploy/kavehmetal-release/frontend.tar.gz /srv/tirexa/frontend.tar.gz
install -m0755 /home/deploy/kavehmetal-release/update.sh /srv/tirexa/update.sh
env APP_ROOT=/srv/tirexa bash /srv/tirexa/update.sh both
DEPLOY
```

نصب‌کننده یک systemd timer به نام `tirexa-market-sync.timer` نصب و فعال می‌کند؛ هر پنج دقیقه موعد دریافت را بررسی می‌کند و از محیط و کاربر سرویس backend استفاده می‌کند. به نصب Celery وابسته نیست. Celery موجود هم همان قفل و فاصله را رعایت می‌کند و درخواست تکراری نمی‌فرستد. launcher برای خواندن محیط سرویس از root استفاده می‌کند، سپس خود فرمان Django با کاربر backend اجرا می‌شود. هیچ رمز یا کلیدی در فایل سرویس تازه نوشته نمی‌شود.

## بررسی بعد از نصب

```bash
sudo systemctl status tirexa-market-sync.timer --no-pager
sudo journalctl -u tirexa-market-sync.service -n 40 --no-pager
```

در پنل، «آخرین بررسی زمان‌بندی» باید تازه شود. ابتدا دریافت دستی بورس کالا را اجرا کنید و تاریخ آخرین معاملات و خطای احتمالی را ببینید. برای بازار جهانی کلید Metals.Dev را وارد کنید، فعال‌بودن منبع و دریافت خودکار را روشن نگه دارید و «ذخیره و همگام‌سازی الآن» را اجرا کنید. داده جدید به دسترس‌بودن منبع و اعتبار کلید وابسته است.

برای توقف کامل اجرای دوره‌ای بازارها، حالت خودکار هر دو بازار را در تنظیمات خاموش کنید؛ این روش هم timer و هم Celery را پوشش می‌دهد. خاموش‌کردن timer به تنهایی، Celery موجود را متوقف نمی‌کند.

## شواهد بررسی اولیه

در GET عمومی سایت در ۲۴ اکتبر ۲۰۲۶، آخرین دریافت موفق هر دو بازار مربوط به ۲۲ اکتبر و آخرین معاملات بورس کالا مربوط به ۲۱ اکتبر بود. API بازار جهانی `provider_configured=false` گزارش کرد. وضعیت سرویس‌های واقعی سرور از این پاسخ قابل تشخیص نیست؛ نصب و دسترسی منبع باید پس از استقرار بررسی شود.

تست‌های API، تنظیمات، فاصله زمانی، قفل، بازیابی قفل منقضی، حفظ داده و تاریخ، و ساخت frontend به‌صورت محلی بررسی می‌شوند. اجرای systemd روی سرور فقط پس از نصب قابل تأیید است.

## اعتبارسنجی محلی

- ۳۵۲ تست بک‌اند و سپس ۳۰ تست متمرکز بازارها/تنظیمات پس از افزودن سه حالت مرزی، همگی موفق.
- پوشش خطی بدنه توابع زمان‌بندی جدید با ابزار استاندارد trace: فایل tasks برابر ۳۰/۳۰ خط و فرمان sync_external_markets برابر ۱۰/۱۰ خط؛ این عدد، پوشش کل پروژه یا پوشش شاخه‌ها نیست.
- ۳۶ تست frontend، lint فایل‌های تغییرکرده، ساخت Next.js و تست مرورگر با پاسخ‌های شبیه‌سازی‌شده موفق. مرورگر، تاریخ امروزِ بدون داده، هماهنگی فیلتر روز جدول و خلاصه، تازه‌شدن هر دو بازار و درخواست دستی در حالت خودکار خاموش را بررسی کرد.
- Django check، بررسی نبود migration جاافتاده، اعتبارسنجی سخت‌گیرانه OpenSpec و بررسی نحو Bash موفق.
- استقرار و اجرای واقعی systemd و منابع بیرونی هنوز روی سرور تأیید نشده‌اند.
